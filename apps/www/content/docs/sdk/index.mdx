`grist-widget-sdk` wraps the Grist plugin API — the JavaScript bridge
between a custom widget iframe and a Grist document — into one hook, a
provider, and a boundary. New here? [What is grist-widget-sdk?](/docs/quickstart/introduction)
covers why it exists and when to reach for the raw plugin API instead.

Already have a scaffolded project from the [template or the CLI](/docs/quickstart)?
Its dependencies and plugin-api script tag are pre-wired — skip ahead to
[Hello world](#hello-world). This page is for adding the SDK to a project
you already have.

## Install

```bash
pnpm add grist-widget-sdk
# or
npm install grist-widget-sdk
# or
yarn add grist-widget-sdk
```

Peer dependencies:

```text
react       >=18
react-dom   >=18
```

## Load the Grist plugin API

The SDK expects the **global `grist` object** at runtime. Add the script in
your app shell:

<Tabs items={["Plain HTML", "Vite (index.html)", "Next.js (app/layout.tsx)"]}>
<Tab value="Plain HTML">

```html
<script src="https://docs.getgrist.com/grist-plugin-api.js"></script>
```

</Tab>
<Tab value="Vite (index.html)">

```html
<!doctype html>
<html>
  <head>
    <script src="https://docs.getgrist.com/grist-plugin-api.js"></script>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.tsx"></script>
  </body>

```

</Tab>

```tsx no-check
        {children}
      </body>
    </html>
  )
}
```

</Tabs>

## Hello world

**[hello-world](/examples/hello-world/demo/)**
is the canonical minimal widget. It is type-checked on every
`pnpm typecheck:examples` run (root `pnpm test` includes that step).

```tsx
import { useGrist, type UseGristOptions } from "grist-widget-sdk"

export const GRIST_OPTIONS: UseGristOptions = {
  requiredAccess: "read table",
}

export function WidgetApp() {
  const w = useGrist()
  const rowKey =
    w.record && typeof w.record.id === "number" ? String(w.record.id) : w.mode

  if (w.mode === "empty") return <p>Select a row.</p>
  if (w.mode === "new-row") return <p>New row flow</p>
  return <p key={rowKey}>Selected row #{String(w.record!.id)}</p>
}
```

Wrap it with `GristWidgetProvider` + `GristBoundary` — the
[template](/docs/quickstart) does exactly this in `main.tsx`. That's
everything you need to:

- Wait for Grist to finish its handshake.
- Render a friendly fallback when the page is opened outside Grist.
- Render an error UI if anything goes wrong, with a retry button.
- Subscribe to the currently selected row.
- Switch between `empty` / `row` / `new-row` modes.

See [Provider & boundary](/docs/sdk/api/provider-boundary) for what each
piece does, and [Raw plugin API vs SDK](/docs/sdk/guide/raw-plugin-api-vs-sdk)
for why you use this package instead of calling `grist` directly.

## What `useGrist()` returns

| Group | Properties |
| --- | --- |
| **Connection** | `status`, `error`, `reload()`, `theme` |
| **Selection and mapping** | `record`, `records`, `mode`, `currentTableId`, `mappings`, `columnMappingStatus`, `mappedRecord`, `resolveMappedColumnId`, `mapBack` |
| **Writes (records)** | `table`, `getTable(id)`, `actionStatus`, `actionError` |
| **Writes (schema)** | `applyActions(actions)` |
| **Reads** | `fetchRows`, `listTables`, `listColumns` |
| **Widget options** | `widgetOptions`, `setWidgetOptions`, `patchWidgetOptions` |
| **Linking** | `setCursorPosition`, `setLinkedRowSelection` |
| **Attachments / REST** | `getAttachmentUrl`, `fetchAttachmentBlob`, `uploadAttachment`, `fetchWithAuth` |

See the [API reference](/docs/sdk/api/use-grist) for every field.

## Asking for write access and declared columns

**[declared-columns](/examples/declared-columns/demo/)**
shows `GRIST_OPTIONS.columns` and `columnMappingStatus` — full source in the
Cheat sheet under [Mappings + column gate](/docs/sdk/guide/cheatsheet#mappings--column-gate).

In the widget configuration panel, the user maps these logical names
to real columns. You consume them via `w.mappedRecord` and
`w.mapBack(...)` on writes — see [Column mapping](/docs/sdk/guide/column-mapping).

## Run a write

**[mark-done](/examples/mark-done/demo/)** is a single-row
`table.update`; its source is in the [Cheat sheet](/docs/sdk/guide/cheatsheet).

For bulk writes, pass an array and the SDK forwards it to Grist as one
`BulkUpdateRecord` action — see
**[bulk-mark-done](/examples/bulk-mark-done/demo/)** in the
[Cookbook](/docs/sdk/guide/cookbook).

For schema changes, see
**[schema-migration](/examples/schema-migration/demo/)**, also
in the [Cookbook](/docs/sdk/guide/cookbook).
