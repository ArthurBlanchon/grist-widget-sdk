A declared reference column reads as its row id, whatever its column shows. A widget that declares a column as `Ref:<table>` or `RefList:<table>`, with no `Text` alternative, now asks Grist for row ids (`expandRefs: false`). Its `mappedRecord` then holds the id in place of `null` and a "not a reference" issue for a column that shows a name. A column that shows a number is no longer mistaken for the row id. Every reference in its `w.record` and `w.records` is an id too. Widgets that declare no reference, or declare `"Text,Ref"` to read the name, read as before. `w.fetchRows()` gives the same ids. A `"Text,Ref"` column declared next to a pure `Ref` one reads the id too, since Grist sends ids or names for the whole read, and the SDK warns about it in the console. The emulator applies a subscriber's own read options (`keepEncoded`, `expandRefs`) to the records it pushes, as Grist does. Like Grist, it now answers `docApi` calls other than `getDocName` (`fetchTable`, `listTables`, `applyUserActions`, `getAccessToken`) only with full access, failing with "Access not granted". A test that read or wrote that way with `read table` access now fails as the widget would in Grist: give the widget `requiredAccess: "full"`, or, for an emulator created without `ready()`, `createGristEmulator({ widgetInteraction: { access_level: "full" } })`.
