`grist-widget-sdk` wraps the Grist plugin API — the JavaScript bridge
between a custom widget iframe and a Grist document — into one hook, a
provider, and a boundary. New here? The [Overview](/docs) says what it does and when to use the
plugin API on its own.

Already have a scaffolded project ([Your first widget](/docs/quickstart))?
Its dependencies and plugin-api script tag are pre-wired — skip ahead to
[Hello world](#hello-world). This page is for adding the SDK to a project
you already have.

## Install

```bash
pnpm add grist-widget-sdk
# or
npm install grist-widget-sdk
# or
yarn add grist-widget-sdk
```

Peer dependencies:

```text
react       >=18
react-dom   >=18
```

## Load the Grist plugin API

The SDK expects the **global `grist` object** at runtime. Add the script in
your app shell:

<Tabs items={["Plain HTML", "Vite (index.html)", "Next.js (app/layout.tsx)"]}>
<Tab value="Plain HTML">

```html
<script src="https://docs.getgrist.com/grist-plugin-api.js"></script>
```

</Tab>
<Tab value="Vite (index.html)">

```html
<!doctype html>
<html>
  <head>
    <script src="https://docs.getgrist.com/grist-plugin-api.js"></script>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.tsx"></script>
  </body>
</html>
```

</Tab>
<Tab value="Next.js (app/layout.tsx)">

```tsx no-check
        {children}
      </body>
    </html>
  )
}
```

## Hello world

A widget is a declaration and a component, in `src/app/App.tsx`:

```tsx
import { defineGristWidget } from "grist-widget-sdk"

export const widget = defineGristWidget({
  title: "Hello",
  requiredAccess: "read table",
})

export default function App() {
  const w = widget.useGrist()
  if (w.mode === "empty") return <p>Select a row.</p>
  if (w.mode === "new-row") return <p>Add the row in Grist.</p>
  return <p>Selected row #{w.record?.id}</p>
}
```

and one call mounts it, in `src/main.tsx`:

```tsx no-check
import { mountGristWidget } from "grist-widget-sdk/app"
import * as entry from "./app/App"

mountGristWidget(entry, { dev: import.meta.env.DEV })
```

That is everything you need to:

- wait for Grist to answer, and show a page when it is opened outside Grist;
- show a screen while access or columns are missing, with a retry;
- re-render on the selected row, in `empty`, `row` or `new-row` mode.

See [Mounting a widget](/docs/sdk/api/app) for what `mountGristWidget()`
renders, and the [Overview](/docs) for why use this package instead of
calling `grist` directly.

## What `useGrist()` returns

| Group | Properties |
| --- | --- |
| **Connection** | `status`, `error`, `reload()`, `theme` |
| **Selection and mapping** | `record`, `records`, `mode`, `currentTableId`, `mappings`, `columnMappingStatus`, `mappedRecord`, `resolveMappedColumnId`, `mapBack` |
| **Writes (records)** | `table`, `getTable(id)`, `actionStatus`, `actionError` |
| **Writes (schema)** | `applyActions(actions)` |
| **Reads** | `fetchRows`, `listTables`, `listColumns` |
| **Widget options** | `widgetOptions`, `setWidgetOptions`, `patchWidgetOptions` |
| **Linking** | `setCursorPosition`, `setLinkedRowSelection` |
| **Attachments / REST** | `getAttachmentUrl`, `fetchAttachmentBlob`, `uploadAttachment`, `fetchWithAuth` |

See the [API reference](/docs/sdk/api/use-grist) for every field.

## Asking for write access and declared columns

In the widget configuration panel, the user maps these logical names
to real columns. You consume them via `w.mappedRecord` and
`w.updateRecord(...)` on writes — see [Declare and map columns](/docs/sdk/guide/column-mapping).

## Run a write

`w.updateRecord(...)` writes the selected row, `w.table.update([...])` many
rows as one action, and `w.applyActions([...])` changes the schema.
[Write data](/docs/sdk/guide/writing-data) explains each.
